Guia

Todo componente do Ultima estende, direta ou indiretamente, ComponenteBase. Componentes que precisam de binding de dados declarativo estendem ComponenteReativo, que por sua vez estende ComponenteBase.

ComponenteBase

Cuida do carregamento do template HTML externo, do isolamento opcional via Shadow DOM e da resolução de caminhos relativos ao próprio módulo do componente (não à página que o usa). 

constructor(propriedades, url_herdeiro)
  • propriedades.templateURL — caminho do arquivo HTML do template, relativo ao módulo .js.
  • propriedades.shadowDOM — true pra isolar em Shadow DOM (mode:'open'); false pra renderizar direto como filhos do próprio elemento.
  • url_herdeiro — sempre import.meta.url da classe filha.

O evento de carregamento

ComponenteBase.EVENTO_CARREGOU ("carregou_componente") é despachado quando o componente — e todos os seus descendentes que também são ComponenteBase — terminam de montar. Ele borbulha (bubbles:true, composed:true) e atravessa fronteiras de Shadow DOM.

Use evento.composedPath()[0], não evento.target. Quando um componente descendente tem seu próprio Shadow Root, o navegador faz retargeting do evento ao cruzar essa fronteira — evento.target aparece como se fosse o próprio elemento que está escutando, mesmo vindo de um descendente diferente. Sem essa checagem correta, um listener pode reagir a carregamentos que não são o dele — na prática isso já causou loops de re-renderização real neste projeto. 
this.addEventListener(ComponenteBase.EVENTO_CARREGOU, (evento) => {
    if (evento.composedPath()[0] !== this) {
        return;
    }
    // aqui sim: o próprio componente terminou de carregar
});

ComponenteReativo

Adiciona reatividade declarativa via atributos data-* lidos do template — a lista completa está na Referência da DSL. Aqui, os conceitos por trás dela.

Dados

get dados()               // retorna os dados atuais
set dados(novosDados)     // grava e re-renderiza, se algo mudou

O atributo HTML data-dados também é observado — mudá-lo de fora (setAttribute) tem o mesmo efeito que usar o setter dados. Escritas que não mudam o conteúdo (comparadas por valor, não por referência) são ignoradas — não disparam re-renderização nem eventos.

Propriedades computadas e observadores

computadas()     // -> Object, derivado de this.dados, somado a todo binding
observadores()   // -> { "caminho": (novoValor, valorAntigo) => {...} }

Sobrescreva computadas() pra declarar valores derivados dos dados brutos — o retorno fica disponível em qualquer binding (data-mapa, data-se, data-classe, data-estilo, data-lista) como se fosse um dado normal. Sobrescreva observadores() pra reagir quando um caminho específico muda de valor entre uma renderização e outra.

Escopo

Cada nível de aninhamento — a raiz do componente, um ramo condicional resolvido, um item de lista — tem seu próprio escopo de dados. Dentro de um item de lista, o nome da variável do laço fica disponível como se fosse um campo normal, e o que vem do escopo pai continua acessível (o escopo encadeia por protótipo). Dois componentes reativos aninhados não compartilham escopo: um filho recebe dados explicitamente via data-mapa='{"data-dados":"caminho"}'.

Reconciliação de listas

data-lista pode reconciliar por chave — quando o item tem um campo de identidade estável (declarado ou inferido de uuid/id), os nós DOM existentes são reaproveitados e movidos em vez de destruídos e recriados a cada renderização, preservando foco, scroll e estado interno de componentes aninhados. Detalhes completos e a sintaxe na Referência.
